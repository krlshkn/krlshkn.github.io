# Контекст и границы SoI

*Информационная система аренды парковочных мест в жилых комплексах «ParkPoint»*

---

## 1. Тема

> Информационная система аренды парковочных мест в жилых комплексах «ParkPoint»

---

## 2. Цель системы

Обеспечить удобный, прозрачный и безопасный процесс аренды частных парковочных мест между владельцами и арендаторами в жилых комплексах.

### Основные задачи системы:

- предоставить арендаторам (клиентам) возможность поиска, бронирования и оплаты парковочных мест через веб-интерфейс с картой и фильтрами
- дать владельцам парковок инструменты для управления своими местами, тарифами, расписанием и доходами
- автоматизировать процесс бронирования и расчёта стоимости (разовые брони + подписки)
- обеспечить безопасное хранение платёжных данных (AES) и обработку платежей
- предоставить администраторам и менеджерам парковочных зон панель управления для мониторинга, модерации и аналитики
- обеспечить коммуникацию между участниками через встроенный чат и систему жалоб / отзывов

---

## 3. Внешние сущности

Для демонстрации потоков взаимодействия между проектируемой системой и внешними сущностями используется контекстный уровень (аналог диаграммы C4).

### 3.1 Пользователи и их взаимодействие с системой

#### 👤 Клиент (арендатор)

- Регистрация и авторизация
- Поиск парковочных зон/мест по карте и адресу
- Просмотр информации о зоне (фото, тарифы, отзывы)
- Разовое бронирование или оформление подписки
- Онлайн-оплата (через привязанную банковскую карту)
- Просмотр / фильтрация / отмена своих бронирований
- Общение с владельцем в чате
- Оставление отзывов и жалоб

#### 🏠 Владелец парковочного места

- Регистрация и авторизация
- Добавление и редактирование своих парковочных мест
- Настройка тарифов (почасовые, суточные, недельные, месячные)
- Управление доступностью мест (active / inactive)
- Подтверждение или отклонение заявок на бронирование
- Просмотр статистики по броням и доходам
- Общение с клиентами
- Ответ на жалобы

#### 🧑‍💼 Менеджер парковочной зоны

- Управление парковочной зоной (адрес, координаты, карта, фото)
- Просмотр мест внутри зоны и их владельцев
- Взаимодействие с администраторами

#### ⚙️ Администратор системы

- Управление пользователями (просмотр, блокировка, смена ролей)
- Управление парковочными зонами (создание, редактирование, статус)
- Модерация заявок на создание зон
- Управление жалобами (просмотр, изменение статуса)
- Просмотр аналитики (графики бронирований, распределение пользователей по ролям)

### 3.2 Внешние интеграции и их обоснование

#### 💳 Платёжная система / банковские карты

Система хранит зашифрованные данные карт пользователей (AES) и взаимодействует с платёжным шлюзом для списания средств при бронировании.

**Обоснование:** безопасность финансовых транзакций — ключевое требование для коммерческого сервиса аренды.

#### 🗺 Картографический сервис (Яндекс API / Google Maps)

Отображение парковочных зон на карте, поиск по адресу, определение ближайших зон.

**Обоснование:** без визуальной привязки к местности сервис теряет основную ценность для арендатора.

#### ☁ Система хранения файлов / объектное хранилище

Хранение фотографий парковочных зон и мест, карт парковок.

**Обоснование:** отдельное хранилище разгружает основную БД и упрощает масштабирование медиа-контента.

## 4. Границы системы

### 4.1 В зоне ответственности системы

- **Веб-приложение (Frontend)** — пользовательский интерфейс для всех ролей: поиск, бронирование, управление местами, личный кабинет, чат, отзывы, админ-панель
- **Backend (Spring Boot)** — бизнес-логика: регистрация/авторизация, управление бронированиями, подписками, тарифами, расчёт цен, уведомления, чаты, жалобы, отзывы
- **База данных (PostgreSQL)** — хранение всех данных: пользователи, парковочные зоны/места, бронирования, подписки, сообщения, жалобы, карты пользователей (зашифровано)
- **Сервис шифрования платёжных данных** — локальная реализация AES для хранения номеров карт
- **Модуль аналитики для администратора** — графики по бронированиям и распределению ролей
- **Модуль уведомлений** — оповещение об изменении статуса бронирования, подтверждении зоны и т.д.

### 4.2 Вне зоны ответственности

- **Обработка реальных платежей и эквайринг** — система только хранит зашифрованные карты и инициирует запрос к внешнему платёжному шлюзу. Реализация собственного платёжного процессинга не предусмотрена
- **Физическая инфраструктура парковок** — шлагбаумы, камеры, датчики занятости мест не входят в систему. ParkPoint управляет только логикой бронирования, но не физическим доступом
- **Юридическое сопровождение сделок** — система не выступает гарантом или посредником в спорах, только предоставляет канал для жалоб и коммуникации
- **Картографический сервис** — используется как готовый внешний API (отображение карты, геокодинг). Разработка собственного картографического движка не предполагается
- **Хостинг и облачная инфраструктура** — система не управляет физическими серверами, репликацией или отказоустойчивостью на уровне IaaS
