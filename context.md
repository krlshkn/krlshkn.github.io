# 1. Контекст и границы SoI

*Информационная система аренды парковочных мест в жилых комплексах «ParkPoint»*

---

## 1.1 Описание системы

**Название:** Информационная система аренды парковочных мест «ParkPoint»

**Назначение:** Платформа предназначена для автоматизации процесса аренды частных парковочных мест в жилых комплексах — от поиска и бронирования до онлайн-оплаты, управления доходами владельцев и разрешения конфликтных ситуаций через систему жалоб и отзывов.

**Что заменяет:** Система заменяет разрозненные инструменты (домовые чаты в мессенджерах, доски объявлений, стикеры на машинах, ручные договорённости) единой цифровой платформой с картой, онлайн-оплатой, встроенным чатом, системой рейтингов и прозрачной отчётностью.

**Типы обрабатываемых операций:**

- Разовое бронирование парковочного места (почасовая, суточная, недельная, месячная оплата)
- Долгосрочная подписка на парковочное место с выбором дней недели и временного интервала
- Управление парковочными местами (добавление, редактирование тарифов, временное отключение)
- Подача и рассмотрение жалоб на пользователей
- Отзывы и рейтингование парковочных зон
- Чат между клиентом и владельцем для уточнения деталей

**Цель системы (миссия):** Обеспечить прозрачный, безопасный и удобный процесс аренды парковочных мест — так, чтобы:

- Клиенты находили свободные места за 1–2 минуты через карту или поиск по адресу
- Владельцы получали стабильный доход от простаивающих парковочных мест
- Администраторы управляли парковочными зонами и разрешали конфликты
- Споры фиксировались через систему жалоб с сохранением контекста (чат, бронирование)
- Платёжные данные хранились в зашифрованном виде (AES) и не были доступны третьим лицам

## 1.2 Границы системы

### Входит в границы платформы

- Создание, хранение и версионирование данных о парковочных зонах и местах
- Регистрация и авторизация пользователей (email + пароль)
- Маршрутизация и проверка бронирований (пересечение слотов, статусы PENDING/CONFIRMED/REJECTED/COMPLETED)
- Расчёт стоимости аренды на основе тарифов владельца
- Интеграция с платёжным шлюзом для списания средств
- Безопасное хранение зашифрованных банковских карт (AES-256)
- Управление подписками (создание, проверка пересечений, автоматическое продление — опционально)
- Чат между клиентом и владельцем
- Система жалоб и отзывов
- Панель администратора: управление пользователями, зонами, жалобами, заявками, просмотр аналитики
- Модерация заявок на создание парковочных зон
- Формирование графиков аналитики (бронирования по дням, распределение пользователей по ролям)

### Не входит в границы платформы (внешние системы)

| Внешняя система | Почему вне границ |
|----------------|-------------------|
| **Платёжный шлюз (эквайринг)** | Система только инициирует запрос на списание и получает результат. Реализация собственного процессинга не предусмотрена |
| **Картографический API** | Отображение карты, геокодирование адресов, поиск ближайших зон — всё через внешний сервис (Яндекс.Карты, Google Maps) |
| **Объектное хранилище (S3-совместимое)** | Хранение фотографий зон и мест вынесено в отдельное хранилище для разгрузки БД |
| **SMTP / push-шлюз уведомлений** | Отправка email и push-уведомлений делегируется внешнему сервису |
| **Хостинг и облачная инфраструктура** | Система не управляет физическими серверами, репликацией или отказоустойчивостью на уровне IaaS |

## 1.3 Внешние сущности и потоки данных

### Пользователи (роли)

| Внешняя сущность | Направление | Данные / события |
|-----------------|-------------|------------------|
| **Клиент (арендатор)** | → Платформа | Запрос на регистрацию (email, пароль); поисковый запрос (адрес, координаты, фильтры); данные бронирования (parking_space_id, start_time, end_time, тип оплаты); данные карты (зашифрованы на фронте); текст жалобы/отзыва |
| **Клиент (арендатор)** | ← Платформа | Список парковочных зон с координатами, описанием и фото; тарифы владельца; статус бронирования (PENDING/CONFIRMED/REJECTED/COMPLETED); уведомления; история броней; список подписок; результаты поиска |
| **Владелец места** | → Платформа | Данные парковочного места (id_parking_zone, тарифы, описание, порядковый номер); изменение статуса доступности (ACTIVE/INACTIVE); подтверждение/отклонение брони; ответ на жалобу |
| **Владелец места** | ← Платформа | Уведомления о новых бронях; список броней с фильтрацией по статусу и дате; статистика доходов (по дням/неделям/месяцам); рейтинг места; список своих мест |
| **Менеджер зоны** | → Платформа | Заявка на создание зоны (адрес, координаты, описание, фото, email менеджера); запрос на редактирование зоны |
| **Менеджер зоны** | ← Платформа | Статус заявки (UNVIEWED/ACCEPTED/REJECTED); список своих зон; список владельцев и мест внутри зоны |
| **Администратор** | → Платформа | Модерация заявок на зоны (ACCEPTED/REJECTED с комментарием); блокировка/разблокировка пользователей; смена ролей; изменение статуса жалоб (RESOLVED/REJECTED); создание/редактирование зон вручную |
| **Администратор** | ← Платформа | Список заявок с фильтрацией по статусу; список пользователей (пагинация, фильтр по роли и email); графики бронирований (последние 14 дней); распределение пользователей по ролям; список жалоб |

### Внешние системы

| Внешняя сущность | Направление | Данные / события |
|-----------------|-------------|------------------|
| **Платёжный шлюз (эквайринг)** | → Платформа | Результат оплаты (успех / ошибка, код ошибки, идентификатор транзакции) |
| **Платёжный шлюз (эквайринг)** | ← Платформа | Запрос на списание средств (сумма в копейках, зашифрованные данные карты, описание платежа) |
| **Картографический API** | → Платформа | Данные карты (плитки, координаты, масштаб), результат геокодирования (адрес → координаты обратно), список ближайших объектов (если API позволяет) |
| **Картографический API** | ← Платформа | Запрос на отображение карты с центром и зумом, запрос на геокодирование адреса, запрос на поиск по адресу |
| **Объектное хранилище** | → Платформа | URL загруженной фотографии, подтверждение сохранения, метаданные файла |
| **Объектное хранилище** | ← Платформа | Файл фотографии (бинарные данные), запрос на удаление файла |
| **Сервис уведомлений (SMTP/push-шлюз)** | → Платформа | Подтверждение приёма уведомления шлюзом, статус доставки |
| **Сервис уведомлений** | ← Платформа | Уведомления: новое бронирование, изменение статуса брони, ответ на жалобу, подтверждение зоны |

**Взаимодействие на диаграмме:**

- **Клиент, Владелец, Менеджер зоны, Администратор** взаимодействуют с платформой через веб-интерфейс
- Платформа интегрируется с тремя внешними сервисами: платёжным шлюзом (оплата), картографическим API (карта и поиск), объектным хранилищем (фотографии зон)
- Все данные пользователей, бронирований, подписок, чатов и жалоб хранятся в PostgreSQL внутри границ системы
- Шифрование платёжных данных (AES) выполняется на стороне бэкенда перед сохранением в БД

## 1.5 Ключевые ограничения и допущения

### Ограничения

| № | Ограничение | Пояснение |
|---|-------------|-----------|
| 1 | **Отсутствие собственного платёжного процессинга** | Платформа не обрабатывает платежи самостоятельно — все финансовые транзакции делегируются внешнему платёжному шлюзу. Система отвечает только за инициирование запроса и обработку результата |
| 2 | **Нет управления физической инфраструктурой парковок** | Шлагбаумы, камеры видеонаблюдения, датчики занятости мест не входят в границы системы. ParkPoint управляет только логикой бронирования, но не физическим доступом |
| 3 | **Не юридический гарант сделок** | Система не выступает гарантом или посредником в спорах, только предоставляет канал для жалоб, коммуникации и фиксации истории |
| 4 | **Зависимость от картографического API** | Картографические данные (карты, поиск по адресам, геокодирование) предоставляются внешним API. При его недоступности платформа переключается в режим списка зон без карты |
| 5 | **Зависимость от объектного хранилища** | Фотографии парковочных зон и мест хранятся во внешнем объектном хранилище. При его недоступности загрузка новых фото невозможна, но существующие зоны продолжают работать |
| 6 | **Зависимость от сервиса уведомлений** | Email и push-уведомления отправляются через внешний шлюз. При его недоступности уведомления ставятся в очередь и отправляются при восстановлении |
| 7 | **Хранение карт — только шифрование, не токенизация** | Платформа не использует токенизацию платёжных данных (передачу карт на хранение платёжному шлюзу с получением токена). Карты хранятся в зашифрованном виде (AES) внутри БД, что накладывает дополнительные требования к безопасности ключа шифрования |

### Допущения

| № | Допущение | Пояснение |
|---|-----------|-----------|
| 1 | **Доступность интернета и браузера** | Пользователи имеют доступ к интернету и используют современный веб-браузер (Chrome, Firefox, Safari, Edge последних версий) с поддержкой JavaScript и HTTPS |
| 2 | **Действительность банковских карт** | Банковские карты пользователей действительны и имеют достаточный остаток для оплаты аренды |
| 3 | **Корректность действий владельцев** | Владельцы парковочных мест корректно указывают тарифы, описание и своевременно обновляют статус доступности мест (ACTIVE/INACTIVE) |
| 4 | **Своевременная модерация администратором** | Администратор системы своевременно обрабатывает заявки на создание зон и жалобы пользователей |
| 5 | **Доступность внешних сервисов** | Внешние сервисы (платёжный шлюз, картографический API, объектное хранилище, SMTP-шлюз) доступны не менее 99% времени в часы пиковой нагрузки |
| 6 | **Безопасность ключа шифрования AES** | Ключ шифрования для AES хранится в защищённом месте (переменные окружения, секреты CI/CD, Vault) и не доступен из кода или БД |
| 7 | **Честность пользователей** | Пользователи не пытаются целенаправленно обходить систему бронирования (многократные отмены, ложные жалобы). Для злоумышленников предусмотрена блокировка аккаунта администратором |
